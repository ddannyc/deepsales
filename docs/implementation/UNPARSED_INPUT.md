# 无法解析输入

无法读取的纯附件或没有可用转写的输入先检查已配置通用转人工条件，再检查持续停止规则。
未命中时，发布配置的“无法解析兜底”决定本轮行为：

- 默认关闭：持久记录 `SKIPPED / UNPARSED_INPUT`。不生成空消息、不改变接待成员、
  不设置人工专属或持续停止。后续有效文字仍正常接待。
- 开启：需要 1–10 条非空话术，每条最多 500 Unicode code points。
  在短数据库事务中随机选定一条并写入运行记录，安全重试复用该选择。
  使用现有翻译适配器按固定语言或已确定的自动语言输出；尚未确定语言时使用配置回退语言。
  翻译开始前预约用量，与本轮其它模型阶段共用逻辑操作，不重复扣计。

翻译在事务外执行，提交前重新检查当前接待权限、输入新鲜度、通用转人工和停止规则。
提供方错误、坏 JSON、空输出或不符合纯翻译约束的结果继续走既有故障处理，不能当正常跳过。
预算不足继续走人工分配边界。未提交的过期结果不会外发，已合法提交消息沿用独立送达机制。

保存只更新草稿，发布及历史还原遵循现有不可变配置版本流程。诊断与用量分析按持久的
`SKIPPED` 状态展示跳过次数；成功兜底记录 `UNPARSED_FALLBACK`。
隔离测试保留同样的配置快照，不读取真实附件或产生真实外发。

部署前需由操作员应用 forward migration `0045_unparsed_input_fallback.sql`。
应用部署不会自动迁移数据库。此实现没有执行生产迁移或部署。
