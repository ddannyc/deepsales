# 会话检索与保存视图

对应 #34 的 T09/T10，前置客户资料和标签已在 #15 本地实现。仅覆盖 Messenger。

五个固定 OPEN 视图和独立关闭历史入口保持原义，增加“团队对话”：当前由人工成员负责、
且调用者有权限查看的进行中会话。没有新增部门或团队成员模型。

`GET conversations` 支持姓名/备注文字、客户、成员、标签、属性、更新时间和视图/消息条件。
搜索按文字子串匹配，百分号和下划线不当通配符；多个成员任一匹配，标签及属性全部匹配。
属性使用现有客户级/会话级定义和类型校验，时间为 UTC 的会话最近更新时间，边界包含。
列表、分页和选中会话的补读使用相同条件；切换条件会清空旧列表并忽略旧请求返回。
客户筛选从客户资料的“仅查看此客户的对话”操作进入，筛选面板显示条件数量并允许清除。

所有条件在数据库执行。AGENT 仍必须有会话频道权限；共享客户资料来源不可见时，姓名、
备注及客户级属性/标签不会被用于匹配。会话级事实也必须有来源频道权限。成员选项只含
当前工作区的有效成员，AGENT 只见与自己有共同授权频道的成员。团队查询不扩大频道权限。

`inbox_saved_view` 持久保存名称、个人/公共范围、创建成员和完整条件。
`GET/POST inbox-views`、`PATCH/DELETE inbox-views/:id` 使用现有会话授权边界和同源保护。
个人视图仅本人可查看或修改；公共视图工作区成员可查看，仅 OWNER/ADMIN 可修改或删除。
公共视图的创建者以外的管理员不能改变其可见范围，避免将他人个人资源改为公共资源。
恢复视图重新执行当前用户的授权查询，分享不会授予额外数据权限。

浏览器 URL 仅保存 `inboxView` ID 用于刷新恢复，不写搜索文字或客户内容。
恢复时先读取当前可用条件；已删除标签、停用/失去共同频道的成员、失效客户或属性/选项
会标为需修复。失效或无权访问的视图不会发起默认全部会话查询。用户需明确修复、
应用或清除。保存的新条件经过严格校验，未知字段不能注入排序/权限或内部查询开关。

迁移 `0019` 只增加保存视图表、约束与索引。由操作员使用直连 URL 先迁移再部署；
应用部署不自动迁移。现有消息、客户、阅读记录和分配历史不变。迁移后默认没有保存视图。
