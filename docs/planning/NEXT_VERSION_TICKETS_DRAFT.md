## 每条实现票的共同验收

- 交付是可独立演示的用户行为，贯通必要持久状态、授权 API、真实 UI 和行为测试，不按 schema/API/UI 分层拆票；复用现有模块、组件和薄适配器。
- 保持 Member 同一模型、单一所有者、分配边界/历史、HUMAN_ONLY、PostgreSQL 权威、OPEN 唯一性、grounding、当前输入新鲜度及合法已提交消息独立送达。
- 全部资料、摘要、测试、诊断、媒体、工具和受众读写遵守工作区/渠道授权；来源跨越不可见渠道时不混合泄漏。AI 历史还原只恢复主配置草稿，不回滚独立资源。
- 使用 [规格的工程默认与测试契约](../implementation/NEXT_VERSION_SPEC.md)，参数不是参考平台公开默认。付费调用预约预算；逻辑重试不重复应用扣计，但实际 provider 尝试/成本分别记录。
- 外部调用不在数据库事务内，消息与动作具有独立持久结果；未知写结果暂停，不盲目重发，恢复不重复成功动作。
- 新 schema 与审阅过的 forward migration/metadata 一并交付；UI 保留加载/失败/取消/权限/部分成功状态，中文界面及可访问性。
- 最小相关单测、真实 PostgreSQL 并发/唯一性/授权测试，以及相应 Worker/Playwright 完整流；集成与 E2E 不并发。通过受影响 format/lint/typecheck/unit/integration/E2E/build 并检查最终 diff。
- 每票包含中性验收数据；不记录用户禁止名称、相关 URL 或私有业务内容，不引入销售专属 handoff 或无需求基础设施。
