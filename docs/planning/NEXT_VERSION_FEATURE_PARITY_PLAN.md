## 当前代码事实

本轮先查询了代码索引，再核对所涉及的实际源码；演示页面、组件库和 E2E 假服务不算真实产品能力。

- 现有会话列表支持 `my / waiting-human / ai-handling / unassigned / all-open` 五个固定视图。列表 API 有 cursor，但页面刷新只取首批列表；没有截图中的搜索、高级筛选、保存视图及客户侧栏。
- 现有 Customer 仅有工作区、名称、头像及时间；ChannelIdentity 有客户与渠道关联。没有联系人电话/邮箱/语言/备注、客户标签、属性、广告来源、客户归属等完整模型。
- 现有 Message 支持文字、附件、PENDING/SENT/FAILED；入站附件支持图片/文件/音频/视频私有存储和显示。人工出站仍是文字，没有素材/话术/内注/翻译/录音链路。入站 provider 解析当前只取 message 事件，未形成读回执及广告 referral 业务链路。
- 现有 AI 配置支持指令、回复语言、一个知识库、四类通用 handoff 开关、关键词和 Draft → Publish。只有当前 editable draft 与 published snapshot，没有测试台、批量测试、历史列表、工具、记忆设置、语音识别、信息采集及回访规则。
- AI 队列当前把本轮未回答客户文字用于检索和生成，没有保留早先 AI/人工回复；#12 补这条基础链路。
- Scheduled handler 与队列目前用于现有维护和恢复，不等于已有回访或群发。数据库没有群发计划、受众快照、规则触发、客户标签/属性、内注或用量账本等对应记录。

核对入口：`apps/web/src/main.tsx` 的 InboxPage / AiMemberPage；Worker 的 handleAiResponseBatch / normalizeFacebookWebhook；数据库的 listConversations / claimAiResponseRun / Customer / ChannelIdentity / Message / AI Member 配置。实现时仍应以最新源码和实际测试为准。

## 关键实现约束

- 复用现有 React 页面、Worker、数据库、队列、私有 R2、分配/送达边界；不因功能数量增加就拆微服务或引入新状态框架。
- 新的持久状态和幂等性仍由 PostgreSQL 决定。涉及 schema 的实现必须附 forward migration、metadata 和操作说明；规划本身不生成空迁移。
- 测试台与真实会话隔离。涉及工具测试时，写操作必须处于沙箱或得到明确授权；不能让“测试”按钮实际群发、分配或修改生产客户。
- 回访属于主动事件，不能简单把已回答的旧客户消息当成新的 AI 输入，绕过现有 run 授权。需要明确触发目的、活动锚点、当前所有者及输入版本，并在提交前检查规则/渠道/预算/会话仍有效。
- 群发每个执行轮次、收件身份和内容块必须有稳定身份与持久去重；随机选择、翻译版本和重试结果需可恢复。
- 保留严格的渠道发送许可。截图中的“普通消息近 7 天”等显示不直接成为后端规则；模板、订阅、营销和通知的审批/资格必须从官方接口核对。普通自动消息继续受已实现的窗口约束，不能借“人工可用”标签给自动化扩大权限。
- 群发或回访的发送动作不能擅自把人工持有的会话分配回 AI；工具和人工 AI 建议也不能绕开 Assignment 或消息提交边界。
- 客户资料、内注、分析、测试及素材均须遵守工作区/渠道授权；不把客户文本、语音、知识或模型提示记入公开日志。
